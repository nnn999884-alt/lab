# pennybot2 — 처음부터 다시 만들기 계획

기존 `pennybot/`(약 3만 줄)은 **그대로 두고**, `v2/` 폴더 안에 새로 만든다. 마음에 들면 갈아타고, 아니면 기존 것을 계속 쓴다.
변경 기록은 `v2/CHANGELOG.md` (루트의 `CHANGELOG.md` 는 기존 버전 것).
`v2/` 안에서 `python -m pytest -q` 로 테스트, 상태 파일은 `v2/state/`.

## 원칙
- 시세는 LS증권 OpenAPI 하나만 (토스 코드 없음). 매매는 모의가 기본, 실거래는 `mode: live` + `PENNYBOT_LIVE_CONFIRM=YES` 둘 다.
- 파일 하나는 400줄 안쪽. 수집기 3천 줄짜리 덩어리 금지 — 기능별로 쪼갠다.
- 파일 입출력은 항상 `encoding="utf-8"`.

## 구조 (2026-11-25 재확정: 허브 + 따로 도는 일꾼)
데이터는 허브 한 곳으로 모으고, 수집·감지·알림은 각각 별도 프로세스(일꾼). 일꾼은 허브하고만 대화(JSON 줄, 로컬 TCP).
허브는 메모리 전달 우선, 저장은 1초 배치. 한 일꾼이 죽거나 느려도 나머지는 계속. 지연 목표: 로컬 전달 수 ms.

## 단계 (끝낸 것에 [x])
- [x] 1. 뼈대: 설정, 세션 캘린더, SQLite 저장소
- [x] 2. 허브·클라이언트·감독자, 재생 일꾼, 급등 감지 일꾼, 알림 일꾼 (프로세스 분리 실행까지 확인)
- [x] 3. LS 시세 일꾼(`workers/ls_feed.py`, `workers/ls/`): 토큰·마스터·웹소켓 → tick/bar. 가짜 LS 서버로 끝까지 검증함. **진짜 LS 연결은 LS 키가 있는 PC 에서 확인 필요** (아래 체크리스트)
- [ ] 4. 일봉 일꾼(야후) + 전날 밤 후보 점수 일꾼
- [ ] 5. 감지 일꾼 추가: 거래 터짐, 공시(SEC 희석), 뉴스 일꾼. 신호에 등급·차트 모양
- [ ] 6. 윈도우 스크립트(`start2.bat`), 일꾼 상태 표시(heartbeat)

## 3단계 실제 연결 확인 체크리스트 (LS 키 있는 PC 에서)
1. `.env` 에 `LS_APP_KEY`, `LS_APP_SECRET` → `python -m pennybot2 hub` 와 `python -m pennybot2 ls` 를 각각 켠다
2. 로그에 `LS 종목 마스터: N종목` → `구독 종목 N개` → 1분 뒤 `수신 {'frames': …, 'ticks': …}` 가 늘어나는지
3. 확인할 것: 마스터 행에 `keysymbol` 이 실제로 들어 있는지(없으면 구독 0개), `clos`·`suspend` 값 형식, 틱 시각(`trdtm`)이 미동부 시각인지
4. 응답 코드 `10003`(전송 한도)·토큰 오류가 반복되면 `SUBS_PER_SEC` 를 낮춘다
